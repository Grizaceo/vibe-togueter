# Reviewed local SDK runtime

The HTTP/Twitch controller never evaluates game exports. IsolatedGameHost reads bounded source bytes and sends them over a bounded JSON-lines pipe to a fresh Linux bubblewrap process. The guest has a separate network/PID/user namespace, no capabilities, a read-only /usr and executor source mount, private /tmp and /dev, and no home/configuration/runtime/credential mount. Its environment is restricted to PATH, HOME and LANG. It cannot access the controller's Twitch or provider credentials. Bubblewrap and user namespaces are prerequisites; startup fails closed if unavailable. The tested host is Linux with /usr/bin/node and usr-merged library paths.

Node's permission flags restrict accidental filesystem/process access further; Node explicitly does not promise malicious-code confinement through those flags. OS namespaces and mount selection are the local boundary. This is not a claim of kernel exploit resistance, signed worker attestation or a general arbitrary upload service. New cloud artifacts, including approved Seed Race, remain outside games/ and need their separate runtime VM; no host fallback is added. MCP installation is blocked in default cloud-vm mode. Explicit trusted-local development can validate in the namespace guest.

The SDK executor creates realm-native globals and parses callback arguments inside the realm. Evaluation, callbacks and view serialization have 50 ms deadlines. A parent 2.5 s startup deadline and 1 s missing-frame watchdog kill stalled guests. Source, output frames and IPC backlog are bounded; V8 has a 96 MiB old-space limit (not a total OS memory quota). Candidate logs are not forwarded into the controller terminal. Stop/reload kills the old guest and settles pending load promises. A guest has no inbound network service.

A runtime failure requests the reviewed Marble Race as fallback, recreates connected players and publishes a visible reason in state/feed. A broken fallback stops gameplay rather than retrying forever. Twitch broadcaster or a moderator identified by the actual IRC mod tag can issue !fallback. Browser nicknames cannot grant this authority. Local POST /admin/fallback additionally requires the streamer confirmation key. No real Twitch moderator rehearsal is claimed by local fixture tests.

Verification: test/game-isolation.mjs covers constructor escape, infinite tick/evaluation, hostile view serialization, replacement/cancellation and recovery. test/fallback-integration.mjs exercises an actual disposable controller and socket while a looping game fails, reconnection of player state and forced fallback authorization. The adversarial read-only reviewer independently inspected descendant /proc metadata: network namespace differed from the controller, environment key names were PATH/HOME/LANG/PWD, and the guest PID disappeared after stop. That probe is separate from the automated constructor test; no credential values were inspected.

References: [Node permission limitations](https://nodejs.org/api/permissions.html), [VM security warning](https://nodejs.org/api/vm.html). The first bubblewrap readiness probe failed because /lib was not mounted; usr-merged read-only library symlinks fixed the loader path. The first cancellation review found an unresolved load promise; the replacement/stop regression now covers it. Initial red isolation log: /tmp/vibe-isolation-red.log; intermediate and final suite logs remain under /tmp/vibe-isolation-*.

A second review reproduced a global context constructor route into the guest process. The null-prototype context regression now blocks it, and the controller independently hashes submitted bytes before accepting the guest version. Missing-file/watch failures and moderator requests during transitions were also repaired. Eight isolation regressions passed on final re-review. UTF-8 stream decoding preserves multibyte names across pipe chunks.
